# Paperclip on Miabi, via GitOps

[Paperclip](https://github.com/paperclipai/paperclip) runs companies of AI agents: org charts,
tasks, budgets, approvals. These `miabi.io/v1` manifests are for a Miabi GitOps source on branch
`main`, path `paperclip`.

| File | Declares |
|---|---|
| `stack.yaml` | Stack `paperclip` |
| `secrets.yaml` | `paperclip-better-auth-secret`, `paperclip-tool-action-signing-secret`, generated by Miabi |
| `databases.yaml` | Managed PostgreSQL 17 `paperclip-postgres` |
| `apps.yaml` | Volume `paperclip-data` (`/paperclip`), Config `paperclip-public-url` (startup helper), app `paperclip` (2026.1106.0, port 3100) |

The app runs in **`authenticated/public`** mode:
- login is required
- auth rate limiting is on
- the first admin is created with a one-time invite, not by whoever opens the URL first

That matters because the generated hostname is public: its certificate appears in
certificate-transparency logs.

## How the public URL is found

Paperclip's public mode won't start without `PAPERCLIP_PUBLIC_URL`. Miabi generates the app's
hostname (`<label>.<base-domain>`, from `externalAccess`) but has no variable that passes it into
the app. So the URL isn't written anywhere, and each boot reads it from the deployment instead:

1. The image's entrypoint runs as usual and drops to the `node` user.
2. `/opt/miabi/public-url.mjs` calls
   `GET {MIABI_SERVER}/api/v1/workspaces/{MIABI_WORKSPACE}/apps/paperclip/external-access` and
   takes the URL of port 3100. It retries for about a minute while the route is created.
3. The shell exports `PAPERCLIP_PUBLIC_URL`, **unsets `MIABI_API_TOKEN`**, and starts the server.
   The server and the agents it spawns never see the key.

If the lookup fails, the server doesn't start, and the reason is in the app's logs (lines start
with `public-url:`). The URL follows the deployment: if the base domain changes or the app moves
location, a redeploy picks up the new one.

## First sync

1. **Create a read-only key for the lookup.** In **Workspace settings → Service accounts**, create
   one (e.g. `paperclip-url-lookup`) with role **viewer**. Give it a key with scope **read** only;
   optionally restrict Allowed IPs to the node's outbound address. Store the key (`mb_…`) in the
   workspace vault as **`paperclip-miabi-api-token`**. The sync fails until this secret exists.
   Read scope can't reveal secrets, but it can read the rest of the workspace, so keep this key
   for this purpose only.
2. **Two constants** in `apps.yaml` describe your install, not the deployment:
   - `MIABI_SERVER: https://miabi.acharfil.me`
   - `MIABI_WORKSPACE: system`

   Change them if the panel or workspace changes.
3. **Create a Git source** for this repository with path `paperclip`. Use the diff view to preview
   the plan, then **Sync now**. Miabi creates the secrets, Config, volume, stack, database and app,
   then deploys it. The first boot runs migrations; allow up to three minutes before it's healthy.
4. **Create the first admin.** Open the app's terminal in Miabi (workspace Admin, on a plan that
   allows shell access) and run:

   ```sh
   npx --yes paperclipai@2026.1106.0 auth bootstrap-ceo --data-dir /paperclip --base-url "$(node /opt/miabi/public-url.mjs)"
   ```

   If the terminal opens as root (`id -u` prints `0`), prefix the command with `gosu node`. It prints
   a one-time invite URL. Open it, sign up, and you're the instance admin.
5. **Connect agent providers** under **Apps → Connections**: a Claude or Codex subscription, or an
   API key.

## Running it

- **Changes go through Git.** Console edits to these resources are reverted by the next sync.
- **Upgrades:** change `tag` in `apps.yaml`. Paperclip migrates its database on boot, and rollback
  restores only the image, so back up `paperclip-postgres` first. Releases are dated
  (`2026.MMDD.N`). Read the release notes for breaking changes.
- **Backups:** the database and the `paperclip-data` volume belong together. The volume holds the
  secrets master key, without which the database's stored secrets can't be decrypted.
- **Deploys interrupt agent runs.** The `recreate` strategy stops the server before starting the
  new one. Paperclip allows 30 s for runs to settle, so deploy when agents are idle.
- **Sign-up:** in this mode anyone who reaches the URL can register an account. Once your admin
  exists, adding `PAPERCLIP_AUTH_DISABLE_SIGN_UP: "true"` to the app's env closes that. Check how
  you'll invite teammates first.
- **Lookup key:** if it expires or is revoked, the next boot can't find the URL and the server won't
  start. The running server is unaffected until then. Replace the vault secret to fix it.
- **Prune:** if you enable it on the source, deleting a manifest deletes the resource. For the
  database, that includes its data.
